The NomNom Data-Generating Process — a structural causal model with known ground truth.

1. Why a Synthetic DGP?

On real data, the true causal effect is unknown. An estimator that returns +0.24 could be correct, or it could be +0.35 biased down to +0.24 by regularization — you cannot tell. This makes causal inference uniquely hard to test.

The NomNom DGP solves this: it is a flight simulator for causal inference. Every structural equation, every coefficient, every noise distribution is specified by us. We can compute the exact ATE by Monte Carlo — draw 200,000 units, run the SCM twice (do(T=1) vs do(T=0)) with the same noise, and average the difference. This gives us the ground truth against which every estimator is checked.

Design principle P5: Methods graduate to real data only after passing synthetic acceptance tests. If an estimator cannot recover truth when we know the answer, it should not be trusted on data where we don't.

3.2 Endogenous Equations

Each variable is computed from its causal parents (the right-hand side of the DAG arrows pointing into it):

W — App-Use History (Measured Proxy)

W is the platform's only window into hunger. It correlates with U (ρ ≈ 0.89) but is not U itself. The platform targets notifications based on W, not U — which is why conditioning on W blocks the back-door path.

T — Notification Sent (Treatment)

The targeting algorithm uses observed variables only: W (app-use), weekend, rain, payday, and Z (jitter). The coefficient on Z (1.1) is deliberately strong — it makes Z a valid instrument. Note: U does NOT appear here — the platform cannot see true hunger. This is the only reason the back-door criterion works.

M — App Opened (Mediator)

where β_TM = 1.6 in the static regime and 0.4 in the holiday regime. U also affects M directly (hungrier users open the app more). This is the only mechanism that changes between static and holiday — everything else is invariant.

D — Loyalty Coupon (RDD Assignment)

Sharp RDD at 500 loyalty points. Users above the threshold get a free-delivery coupon which increases order probability. This creates a regression discontinuity design episode at nomnom/episodes/rdd_coupon.py.

Y — Order Placed (Outcome)

Coefficients: U=0.5 (hunger drives orders), weekend=0.55, rain=0.35, payday=0.3, M=0.9 (mediation), D=0.5 (coupon). Treatment effect depends on segment:

Segmentτ (direct T→Y, logit scale)Probability uplift
New users (40%)0.4~1.5 pp
Loyal users (60%)1.1~3.5 pp

The total effect includes the mediated path: T→M (+1.6 × M→Y 0.9 = +1.44 on logit scale via M). This is why the total ATE (~+0.24 on probability scale) is larger than the direct effect alone.

S — Engagement Score (Collider)

Since T and Y are both causes of S, conditioning on S opens a back-door path between T and Y (Berkson's bias). NEVER adjust for S.

NC — Battery Drain (Negative Control Outcome)

NC shares confounder U with Y but has no causal effect from T. If our adjustment is correct, the estimated T→NC effect should be ~zero. A non-zero result is a smoke alarm: residual confounding exists.

4. Regime Switching (Holiday Drift)

The nomnom/regimes.py module defines environment switches via a frozen dataclass:

@dataclass(frozen=True)
class Regime:
    name: str = "static"
    beta_tm: float = 1.6      # T → M coefficient
    base_open: float = -1.2   # intercept of M equation
    p_rain: float = 0.30

STATIC  = Regime()
HOLIDAY = Regime(name="holiday", beta_tm=0.4, base_open=-0.6, p_rain=0.15)

The holiday regime changes exactly one causal mechanism — the T→M coefficient drops from 1.6 to 0.4. Users habituate to notifications during holidays: seeing a notification is less likely to make them open the app. The base rate shifts (base_open from -1.2 to -0.6) and rain probability drops (0.30 to 0.15 — fewer rainy days in holiday season).

Key property: The Y mechanism (order given hunger, app-open, and context) is invariant across regimes. The EVOLVE station's mechanism-stability monitor detects that M's conditional distribution degrades while Y's does not — correctly localizing the drift to exactly the mechanism we changed.

5. Monte Carlo Ground Truth

The ground_truth() function computes the exact ATE by simulating the do-operator:

def ground_truth(regime=STATIC, n_mc=200_000, seed=999):
    rng = np.random.default_rng(seed)
    exo = _draw_exogenous(n_mc, rng, regime, DEFAULT_PARAMS)
    # Run SCM twice with SAME noise, different T
    y1 = _structural(exo, regime, DEFAULT_PARAMS, t_value=np.ones(n_mc, int))["Y"]
    y0 = _structural(exo, regime, DEFAULT_PARAMS, t_value=np.zeros(n_mc, int))["Y"]

This directly computes E[Y | do(T=1)] − E[Y | do(T=0)] by forcing T to 1 (or 0) for every unit, regardless of what the targeting algorithm would normally assign. The noise is shared between the two runs — each unit serves as its own control.

With n=200,000, the Monte Carlo standard error is ~0.001 — more than precise enough for checking whether an estimator's 95% CI covers the truth.

Typical values — static regime: ATE ≈ +0.241 (μ₁ ≈ 0.613, μ₀ ≈ 0.372). Holiday regime: ATE ≈ +0.191 (smaller because the mediation path T→M→Y is weaker).

6. Why This Design Exercises Every Causal Concept

ConceptHow the DGP exercises it
ConfoundingU→W→T creates a back-door path; without adjusting for W, the naive estimate is biased up by ~0.10
MediationT→M→Y means the total effect ≠ the direct effect; adjusting for M blocks the mediated path
Collider biasT→S←Y — conditioning on S (engagement) opens a spurious path; the DGP's S equation guarantees this
InstrumentZ→T with strong coefficient (1.1), Z↛Y directly, Z independent of confounders — valid IV
Negative controlNC shares U with Y but has no T→NC path — a built-in falsification test for residual confounding
Heterogeneityτ differs by segment (0.4 vs 1.1) — CATE ≠ ATE; the ATE weights them by P(segment)
RDDD = 1[L≥500] creates a sharp discontinuity — exercises local randomization and bandwidth selection
Drift detectionHoliday regime changes β_TM alone — the mechanism-stability monitor must localize the drift to M
